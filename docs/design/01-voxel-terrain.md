## 1. 一句话

地形不再转成三角形。Box3D 里加一种只能挂在静态刚体上的新形状 `b3_voxelShape`：**每格存一个「方块碰撞体」编号**，碰撞体 = 格内的几个盒子 + 材质（就是 MC 的 `VoxelShape.toAabbs()`）。算接触时只看刚体附近的格子，**当场**把盒子「露在外面的那部分面」拼成三角形，交给 Box3D 现成的三角形碰撞和防鬼碰撞那一套。改一个方块 = 改一个编号，不重建任何东西。

## 2. 为什么 A 不行、B 怎么绕开（给决策用的对照）

| | A：每段一个三角网格 | B：体素形状 |
|---|---|---|
| 半格方块的鬼碰撞 | 面剔除只认整格邻居 ⇒ 半格旁边的面整片留着 ⇒ 一条边叠 3–4 个三角形，Box3D 的 `identifyEdges` 只认「恰好两个三角形共用」的边 ⇒ 处处磕 | 露出部分按**盒子之间的几何**精确算（§4.2），平边 / 非平边也按几何判（§4.3），不依赖网格拓扑 |
| 段与段的接缝 | 要带邻段一圈建「上下文网格」再抄标记，贵 | 格子数据直接读得到邻段（§3.3），接缝和段内一样处理 |
| 方块变化 | 整段重建：均值 3.8、最大 43 ms | 改一个编号 + 让附近的接触重算：微秒级（§5） |
| 刚体被压进 / 被方块埋进地形 | 三角形单面，压过了就掉下去 | 格子知道「这里是实心的」，往最近的露出面推出去（§4.5） |

## 3. 数据

### 3.1 碰撞体表（每个物理 world 一张）

- 一条碰撞体 = 格内 0–1 坐标里的 **1–64 个轴对齐盒** + 一个材质下标。编号 0 = 空（空气、没有碰撞的方块）。
- 来源：Java 侧对每个方块状态取 `getCollisionShape(level, pos, CollisionContext.empty()).toAabbs()`。**按内容去重**（盒子列表 + 材质一样就是同一条），所以带随机偏移的方块（竹子、滴水石锥）也能进表，只是多几条。
- 材质表：Box3D 的 `b3SurfaceMaterial`（摩擦、弹性、`userMaterialId`…），碰撞体存下标。方块的滑度换算成摩擦（默认 0.6 → 0.6，冰 → 很小，史莱姆块…），换算规则在 Java 侧，是注册表，别的 mod 可以为自己的方块指定。
- 只增不删，表小（原版几百条量级）。**每个 world 一张**而不是全进程一张：表只被拥有这个 world 的线程改，不用加锁（服务端和客户端的 world 在不同线程上跑）。
- 超过 64 个盒的碰撞体（只有模组方块可能）：退成 MC 自己 `optimize()` 后的形状，还超就用包围盒，打一次日志。

### 3.2 段

- 一段 = 16×16×16 个 `uint16` 编号（8 KB），外加：所在段坐标、指向周围 26 个段的指针（没载入的是空）、所属的静态刚体和形状 id。
- 每段一个静态刚体（放在段的世界坐标角上，双精度）+ 一个体素形状，包围盒固定是整段 ⇒ 改格子**不动宽相**（调研 §3）。
- 全是空气的段不进 Box3D（和 A 一样）。

### 3.3 网格对象（`b3VoxelGrid`，每个 world 一个）

段和段之间要互相读边界格子（算露出面、判平边），所以由一个对象统一管：

```c
b3VoxelGridId b3CreateVoxelGrid( b3WorldId world, const b3VoxelGridDef* def ); // def 里带形状模板：过滤分类、事件开关…
int  b3VoxelGrid_AddMaterial( b3VoxelGridId, const b3SurfaceMaterial* );
int  b3VoxelGrid_AddCollider( b3VoxelGridId, const b3AABB* boxes, int boxCount, int material ); // 返回编号 ≥ 1
void b3VoxelGrid_SetSection( b3VoxelGridId, int sx, int sy, int sz, const uint16_t cells[4096] ); // NULL = 卸掉
void b3VoxelGrid_SetCells( b3VoxelGridId, const b3VoxelCellEdit* edits, int count );             // 世界格坐标
// 查询结果里的格子：形状 id + 特征键 → 世界格坐标 / 碰撞体编号
```

`SetSection` 在内部建 / 删那一段的静态刚体和形状、接好 26 个邻居指针、让邻段贴边处的接触重算（§5）。Java 不用管每段的刚体句柄。
⇒ 这层是 Box3D 的通用功能（「格子地形」），不写死 MC；格子大小固定 1、段边长固定 16。

## 4. 接触怎么算（核心）

### 4.1 选哪条路

调研 §11 摆了两条：

- **盒子路线**：每个盒子当一个实心凸包，用 Box3D 的盒对盒 / 盒对胶囊 / 盒对球。问题在盒子之间的内部接缝：相邻两块石头，滑过去的箱子会被后一块石头的侧面「顶一下」（经典鬼碰撞）。要压住它，就得在分离轴测试里**排除被盖住的面和不凸的边**——这等于为三种形状重写一遍 Box3D 的凸包碰撞（上游 `convex_manifold.c` 1600 行、调过很多轮），新写的出错概率最大。
- **露出面路线**：只取盒子露在外面的那部分面，拆成单面三角形，交给 Box3D 现成的「三角形对球 / 胶囊 / 凸包」和 mesh 那一套防鬼碰撞、聚类、缩点、warm start。Box3D 的高度场就是这么干的（格子数据 + 当场取三角形 + 预先算好的边标记，`height_field.c:515`），我们照着把「一张高度图」扩成「三维的格子」。

**推荐露出面路线**：大部分代码是 Box3D 自己的、已经调好的；我们要新写的是「露出部分怎么算」「边是不是平的」「埋进去了怎么推出来」三件，都只依赖格子数据，好测。盒子路线天然「实心」的好处，用 §4.5 的推出规则补上。

### 4.2 露出部分

一个盒子的某个面 = 一个矩形。拿所有**贴着它、方向相反、在同一平面上**的面（同一格里别的盒子、隔壁格的盒子，跨段也算）从这个矩形里减掉，剩下的就是露出部分（0 到若干个矩形）。

- 整格贴整格（最常见）：直接判「全盖住」，不算矩形。
- 结果按 (碰撞体 A, 方向, 碰撞体 B) 缓存在网格对象里（只和两个碰撞体有关，和位置无关），第一次遇到才算；一格的面被多个盒盖住时，把各自的结果再相减。
- 剩下的矩形超过 16 个（极少）：这个面当作整面露出，打一次日志——宁可多一个可能的鬼碰撞，不能漏碰撞。

例子：石头旁边是下半砖 ⇒ 石头的那个侧面只露出上半截（y 0.5–1）；半砖铺满一片 ⇒ 半砖的侧面互相全盖住，只剩顶面——这正是 A 量出来磕得最厉害的两种情况。

### 4.3 边标记

Box3D 只用「平边」这一种标记（`mesh_contact.c:926-965`：凸包 / 胶囊的暂定接触三条边都平就丢、平边已被别的三角形接住就丢；凹边故意不丢，防止从凹角穿过去）。我们按几何判：

- 矩形的对角线：平。
- 矩形的边：**越过这条边，同一平面上紧接着还是露出的面**（同一个面的另一块露出矩形、同格别的盒子、隔壁格的盒子，跨段也算），而且整条边都是 ⇒ 平；否则不平。
- 只有一部分是平的边：第一版按「不平」处理（偏保守：可能留一点点鬼碰撞，但不会穿）。量出来有问题再在那个点把矩形切开。

### 4.4 每一步的流程（照 `b3ComputeMeshManifolds` 写成 `b3ComputeVoxelManifolds`）

1. **候选**：刚体 B 的包围盒外扩（同 mesh 的查询盒）碰到的格子，按格子编号升序；每格每盒每面每块露出矩形的两个三角形，各有一个**特征键** = `格子(12 位) | 盒(6) | 面(3) | 矩形(8) | 三角形(1)`（矩形 = 露出矩形 × 16 + 切开后的片号，§12.4；255 留给推出），天然升序，能直接沿用 mesh 的「按下标归并旧缓存」。B 没走出查询盒就不重新找候选（同 mesh）。上限沿用 512 个三角形。
2. **窄相**：三角形顶点从格子坐标现算；调 Box3D 的 `b3CollideTriangleAndSphere / Capsule / Hull`。
3. **防鬼碰撞**：mesh 那一套原样。它按顶点编号认「同一条边 / 同一个顶点」——我们的顶点编号只要求**在这一次计算里**一致，用量化后的坐标去重即可（顶点都从同一份盒子数据算出来，量化去重是稳定的）。
4. **跨段**：一个刚体压在两段上 = 两个接触，各算各的，互相看不见对方接住了哪条边。补丁 0001 的规则（「平边上的边 / 顶点特征，法线又不是面法线 ⇒ 丢掉」）在体素这里对所有边成立，因为平不平是按几何判的、包括邻段。
5. **聚类、缩点、warm start、材质平均、滚动阻力**：mesh 的代码照用；材质从「三角形的材质」改成「特征键 → 碰撞体 → 材质」。

### 4.5 埋进方块里：往外推

单面三角形管不了「已经在里面」：刚体被玩家推进地里、方块被放到刚体身上、活塞推进来，中心一旦越过表面，背面剔除让它什么都碰不到，会一路掉下去。MC 的地形是实心的，所以加一条：

- B 的参考点（球心 / 胶囊轴线上离盒子最近的点 / 凸包质心）落在某个盒子里面 ⇒ 额外生成一个接触：法线 = 这个盒子**露出的**面里推出距离最短的那个方向，深度 = B 在这个方向上的最深点到那个面的距离。
- 这格整个被包住（六面都盖住）⇒ 沿六个轴各往外找最近的空格（最多找 4 格），往最近的那个方向推；都找不到就往上。
- 只在参考点真在实心里时才触发，平常的接触（浅穿透）不受影响。

## 5. 改格子

一个方块变了，Box3D 里有四层缓存会让这次变化「看不见」（调研 §4.6：接触回收整步跳过、候选列表不刷新、睡着的岛不更新、每个键的分离轴缓存）。`b3VoxelGrid_SetCells` 只能在 step 之外调，做：

1. 写编号。
2. 这格在段的边上 ⇒ 邻段贴边处的露出面也变了，邻段一起处理。
3. 遍历这一段（和受影响的邻段）静态刚体的接触链表——一段一个形状，链表就是它的全部接触，**包括睡着的和还没碰上的**——包围盒碰到「改动格子外扩一格」的：清掉回收标志、清空查询盒和候选缓存、叫醒另一侧的刚体。
4. 不销毁接触、不动宽相 ⇒ 别处的 warm start 都保留。

新载入一段正好压在一个醒着但不动的刚体上：形状用 `invokeContactCreation` 建，让宽相马上找配对（调研 §3）。静态树不会自己重建：段进出多了以后，在 Java 侧按「进出次数」隔一阵调一次 `b3World_RebuildStaticTree`。

## 6. Box3D 里要碰的地方（fork 的改动面）

主体放新文件（`voxel.c`、`voxel_contact.c`、`voxel.h`），老文件只在分派点加分支，方便以后合上游。按调研 §12：

- 必须：枚举值和 union；创建 / 访问；只许静态、不许当 sensor；包围盒；接触注册三行 + 多 manifold 开关 + `b3UpdateContact` 分支；改格子的失效；CCD 分支（露出的三角形喂给现成的 `b3MeshTimeOfImpactFcn`）；四个查询分支（§7）；材质约 8 处分支（共享表，不给每段拷一份材质——几千段会占几十 MB）；`b3ValidateContacts` 分支。
- 明确拒绝：录制回放（`b3World_StartRecording` 发现体素形状就拒绝）；动态 / 运动学体素；`b3Body_SetType` 改出静态。
- 不用改：岛 / 睡眠、爆炸、风、质量、宽相。
- 顺手修的上游 bug（今天就存在，和体素无关）：`b3Body_SetType` 遇到 compound / 高度场提前返回时没解锁世界（`body.c:1605,1623`，之后整个世界锁死）；CCD 不检查 pre-solve 回调是否为空（`solver.c:439-445`）；`b3Shape_GetClosestPoint` 对 mesh / 高度场 / compound 直接崩（`shape.c:1861-1885`）。

## 7. 查询

| 查询 | 做法 | 起点在方块里 / 方块表面上 |
|---|---|---|
| 射线 | 按格子走（DDA），每格对盒子求交 | **穿过这个方块、继续往前**（review 后改，§12.2）：Box3D 的最近射线丢掉 fraction 0 的命中是「丢掉整个形状」，一段是一个形状，不穿过就会把整段都漏掉。贴着面平行走不算碰到——⚠️ 只限面的另一侧是空气；两个实心盒之间的接缝不是面，压在接缝上（整数坐标竖直往下打两块地板之间）算在方块里（2026-11-07，fork `8dd615b`，`VoxelTerrainTest.aRayAlongTheSeamBetweenSolidBlocksHitsThem`） |
| 形状扫掠、角色 mover | 露出的三角形（和接触一致，不会被内部接缝挡住） | 同 mesh：在面背后的忽略；扫掠一开始就贴着 = fraction 0 命中 |
| 重叠 | 实心盒子 | 算重叠 |

⚠️ 射线和 MC 的 `clip` 不同：MC 起点在方块里会在起点命中；我们跟 Box3D 对其他形状的规矩走。

结果里的「三角形下标」放特征键，配一个函数换回世界格坐标，Java 侧就能知道打中的是哪个方块。

## 8. Java 侧

- **保留**：`LevelPhysics`、实体代理、`physics` 包、`TerrainStreamer` 的按需 / 延迟卸载 / 请求区域逻辑、方块变化钩子。
- **改**：流送「建一段」= 读这段的方块状态 → 换成碰撞体编号 → `SetSection`（只拷 8 KB，预算可以放宽很多）；方块变化排进队列，下一次 step 前一次性 `SetCells`。新类 `mc/terrain/BlockColliders`：方块状态（带偏移的连位置一起）→ 碰撞体编号，每个 world 一份。
- **删**（方案 A 专用）：`SectionMesher`、`createMeshWithContext` / `meshGetEdgeFlags` 及其 C 函数、`MeshSeamTest` 的上下文部分、`SeamProbeGameTest`（DIAG-TEMP，改写成正式的接缝 GameTest）、`TerrainBenchCommand`（DIAG-TEMP，§9 量完删）。`MeshData` 和 mesh 形状本身留着（通用功能）。
- **已知限制**（第一版不做）：碰撞形状随方块实体变化、却不改方块状态的方块（潜影盒开盖、正在被活塞推的方块）——只在方块状态变化时更新；`CollisionContext` 相关的方块（脚手架、细雪）按「空上下文」取形状。

低级的记下没修（等用户决定要不要做）：
- `SetSection` 新建一段时不叫醒段里睡着的刚体（`SetCells` 会）。只影响「睡在别的刚体或非地形静态体上、又被新载入的段包住」的刚体。载入区块时故意不叫醒，因为区块里本来就有这些方块。
- 网格定义里的 `invokeContactCreation` 用调用方的值，没有强制打开；关掉的话，醒着不动的刚体要等它动了才和新段配对。Java 侧用默认值（开）。
- 胶囊的推出参考点取的是中点，§4.5 写的是「轴线上离盒子最近的点」：一头埋进去、中点在外面时不推（露出面的接触一般能接住）。
- 推出选「最近的、哪里露出就算」的面，不看参考点正对的那块是否露出：楼梯里可能先往上推进上半格、下一步再从侧面出来。
- 重叠查询对「正好贴着」的处理上下不对称（贴在方块顶上不算，贴在方块底下算）。
- `SetSection` 先数非空格、再把非法编号改成 0：传非法编号时段会多数一格，清空后不删段。
- 世界在 step 中（被锁）时调 `b3DestroyVoxelGrid` 会释放段却留着刚体。Java 侧不会在 step 里调。
- 一个面被盖成超过 15 块露出矩形时整面算露出，那几条内部边会有接缝磕碰（五个以上不相连的遮挡块才会出现）。
- 改格子时邻段那一侧的失效范围可能是零厚度（多叫醒贴着那个平面的刚体，无害）。
- 顶点编号按 1/2048 格量化去重，不在 1/16 网格上的模组碰撞箱可能把很近的两个点当成一个。
- 快照 / 回放路径不认 `voxelTriangles`（开始录制会拒绝体素形状，今天走不到）；没有体素段的网格存在时开始录制，之后建的段不会被录进去。
- 两个「只警告一次」的静态标志在工作线程里写，良性数据竞争（和上游 `s_once` 一样）。
- `AddCollider` / `AddMaterial` 不能在 step 里调（会改工作线程在读的数组），文档没写；Java 侧有世界的单线程检查兜着。
- （上游补丁 0001 继承）球的暂定接触在被「平边鬼碰撞」规则丢掉之前已经登记了顶点，可能挤掉同一顶点上一个正常的接触，影响一步。

1. **「只有一部分是平的边」按不平处理不够**（§4.3 当初就说「量出来有问题再切开」）：石头顶面挨着楼梯上半格，那条边一半平（楼梯顶面接着）一半不平（楼梯踏面掉下去）⇒ 整条算不平 ⇒ 球 2 m/s 被顶起 0.57、箱子 6 m/s 2.1 m/s。改成：**在平不平变化的地方把露出矩形切开**（每块的每条边要么整条平、要么整条不平；一块最多切 16 片，超了退回旧做法）；判平边时「越过这条边的那一侧被覆盖」也算上被切开的同一面。特征键的 rect 段从 4 位改 8 位（露出矩形 × 16 + 片号，和查询范围无关，warm start 稳定）。
2. **顶点上的鬼碰撞**：横放的胶囊轴线正好压在石头和楼梯顶面的接缝上 ⇒ 它下面那个三角形报的是「边」接触（Box3D 只在「面」接触时登记边），旁边三角形的角点（挨着真实的落差）就给了一个斜法线 (−0.2, 0.93, 0.3)，冲量 1.38，把胶囊往旁边推、转起来、最后掉下去（`Body.contactPoints` 看到的）。规则：**体素三角形顶点上的接触，法线必须往外越过那个顶点上至少一条「真实（不平）」的边，否则是鬼**（只越过平边 = 曲面还在继续，邻三角形会面接触）。JUnit `aCapsuleAcrossAStairsUpperHalfIsNotTurnedAsideAtTheSeam`。

⚠️ 剩下一个**不是接缝**的现象，记下不修：同一场景里横放胶囊（0.7 宽）架在楼梯上半格（0.5 宽）上，两头悬空；回到石头时，胶囊两头从石头侧面上沿（楼梯踏面上去的真实台阶角）上方 1 cm 内擦过，Box3D 的**推测接触**（分离 +4 mm 时就按线性预测加冲量）把它抬了 0.39 m/s、减速 7%。这是真实凸角 + Box3D 推测接触的普遍行为，换成三角网格一样会有。接缝测试的横胶囊改成放得下的尺寸（和 JUnit 一致）。

#### 12.6.2 补测试时抓到的

1. **埋在大块实心里的刚体卡在格子边界上**：推出每步 0.05（3 m/s），从 x.5 起推 10 步正好停在整数上；那一点被当成「不在任何盒子里」⇒ 不推了，0.5 s 后睡着。改成半开区间（`eaf509b`）。`VoxelDetailTest.aBodyBuriedDeeperThanTheSearchStillComesOut`。
2. **段界上一度的斜法线把箱子推歪**（以前的 GameTest 碰巧没撞上）：GameTest 每次放的位置不同，段界落在两个楼梯之间时，2 m/s 的箱子被转了 40°、从楼梯上半格上甩下去（竖直 5.4 m/s、角速度 11 rad/s）。以前接缝 GameTest 不断言「滑到头」，卡住的箱子也算过。
   - 原因：箱角刚过段界，这一段的三角形报的是边接触，法线差一度（和面法线点积 0.9998，在 Box3D「接近面法线就留着」的 0.999 以内）。段内这种接触会被相邻三角形的面接触挡掉（Box3D 的 found edges），跨段时挡它的那个面接触在另一段的接触里。
   - 修：体素的边 / 顶点接触，法线和面法线点积 ≥ 0.999 ⇒ 用面法线（`1caa529`）。
   - 量：16 种段界位置 × 4 种地面 × 4 种形状 × 3 种速度，加上 4 个 GameTest 实际放过的位置。修前坏 7 次（最坏竖直 5.4 m/s、角速度 11.3），修后 0 次（最坏 0.0008 m/s、0.007 rad/s）。GameTest 随机位置连跑 7 次全绿。
   - 测试：JUnit `aBoxSlidingOverStairTopsIsNotTurnedWhereverTheSectionBorderFalls`（每种段界位置）；接缝 GameTest 现在断言滑到头、出口速度 ≥ 95%、角速度 < 0.1。
3. **别的 mod 删了实体代理的刚体** ⇒ 下一 tick 驱动它就抛异常 ⇒ 配上 #11 的「出错就停」，整个 Level 的物理停掉。review 原来记成低级，因为 #11 升成中级，修了：跳过并移出表，下次再建。GameTest 测了。
4. `Body.bounds` 是 Box3D 存的包围盒，动过的刚体每边多 0.02（推测距离），文档补上。

#### 12.6.3 ⏳ 等用户定：大物体超过 512 个候选三角形

- Box3D 给一个凸形对一段最多 512 个候选三角形（`B3_MAX_MESH_CONTACT_TRIANGLES`，上游的网格也一样）。格子按 y、z、x 取，超了的直接丢，丢的是 z 大的那几排。
- 量（楼梯地面，每格 6 个三角形）：6 × 6 的箱子没事；10 × 10 的接触点只剩 z 小的一半，还平着是因为重心还在支撑范围里；**12 × 12 直接陷进去**（从 1.5 掉到 0.5，没有接触点）。整格地面每格 2 个三角形，约 16 × 16 才到；栅栏这类每格三角形多的更早。
- 只影响**单个凸形**很大的刚体；拼起来的结构是很多小形状，各算各的。
- 三条路：(a) 编译时调大上限（Box3D 留了宏；大物体每步多算三角形、多用临时内存）；(b) 超了以后离刚体近的优先，不按编号；(c) AB 混合（§11 第 4 条）：共面相连的露出面合并成大块，平地一段只剩几个三角形，楼梯一排一块，从根上少三角形，也把平地上每步慢 1.8 倍（§12.5）拉回来。建议 (c)；做之前先 (a) 顶着。
- 测试现在只断言上限以内的情况（6 × 6，四个角都有接触点）。
- **✅ 用户 2026-10-28「你决定就好」⇒ 我定的**：(a) 现在就做，(c) AB 混合（就按上面的理解：格子数据照 B，共面相连的露出面合并成大块缓存）排在多线程 / API 第 2 批之后单独做。
  - (a) 已做：`native/CMakeLists.txt` 给 box3d 加 `B3_MAX_MESH_CONTACT_TRIANGLES=2048`（一整段楼梯在一个刚体下 1536 个）。旧上限以下不多花：只是 arena 借出的临时内存大一些。测试改成 6、10、12、14 格宽的箱子都平放在楼梯上、四个角都有接触点（`aBoxOnStairsIsHeldUpUnderAllFourCornersUpToAWholeSection`），没有容量警告。
  - 顺带抓到一个构建 bug：改 `native/CMakeLists.txt` 里的编译定义会重新配置，但 `buildNative` 只看源码目录，被当成「最新的」跳过 ⇒ 库没重编，测试还在跑旧上限。`buildNative` 的输入加上三个 CMakeLists。
  - **2026-10-29 重新评估 (c)：现在不做。** 用户问「AB混合合适吗？合适的话就做，也不是说要强行做」，我的判断：
    - 它要解决的两件事都已经不痛：上限的问题 (a) 已经顶住（一整段楼梯压在一个刚体下也够；比这还大的单个凸形在 MC 里几乎碰不到）；速度上平地慢 1.8 倍，换成绝对值是 256 个同时在动的刚体每 tick 多约 0.5 ms，几十个刚体的正常玩法里量不出来。
    - 代价落在最难做对的地方：合并以后的大块和旁边没合并的小格子之间有 T 形接缝，这正是鬼碰撞的经典来源；而现在的防鬼碰撞（平边、顶点、段界斜法线，§12.4 / §12.6.2）都是按「每格一个面」调出来、量过的。三角形不再一格一个，命中 / 接触点按三角形查格子（`b3Shape_GetVoxelCell`）也要改成按点查。细长的大三角形对 Box3D 的接触质量也不友好。
    - ⇒ 留着当备选：真实玩法里量出地形接触是瓶颈（几百上千个刚体同时在平地上动）再做；那时先比一下第 3 批（共享线程池）能拿回多少。

#### 12.6.4 记下没修的低级项

Java / API（大多放进多线程和 API 设计稿一起讨论）：
- 热路径分配：`EntityProxies` 每 tick 一个列表 + 每个刚体一个 AABB；`setTransform` 的四元数；`contactPoints` 每个点 3 次 JNI；重叠 / mover 每次 `malloc`。
- 每 tick 每个刚体约 3 次 JNI；每个动态刚体每 tick 一次 `getEntities`（15 骨的 ragdoll = 15 次）。
- 没有 `Cleaner` 兜底：忘了 `close` 的世界永久占一个槽（共 1024）。
- `B3` 是 public、`Box3DException` 在 `jni` 包；`setConsumers` 只有一个谓词，最后一个 mod 说了算；调参字段 public。

MC：
- `wanted` 表里从没载入过的段不清（小泄漏）。
- 区块载入时，邻段贴边一圈格子总是重算（靠近一堆已载入段时每区块几 ms）；原版只有活塞会横跨区块边。
- `dynamicShape` 的方块（竹子、滴水石锥、潜影盒…）一律当「高形状」：改一个重算 27 格，所在段走 18³ 的慢路径。
- `TerrainMaterials.fill` 每次 `new SurfaceMaterial()`（一次同步 + 一次 JNI）。
- 超过 64 个盒子的形状没先 `optimize`，警告不说是哪个方块。
- 从不调 `b3World_RebuildStaticTree`（段来来去去后静态树会变差）。
- 传送后代理带着旧的运动学速度漂一 tick；提供者说「不要代理」的实体每 tick 重问。
- 调试绘制：换维度后最多 10 帧画旧的线；所有段同一帧刷新（每 10 帧一顿）；分配多。
- 本地库加载失败后，每次 `LevelPhysics.of` 都重进同步的 `load` 并新建异常；Linux `noexec` 的 `/tmp` 没有后备目录。
- GameTest 失败 / 超时时，留在 Level 物理里的刚体不清（私有世界的测试不受影响）。
- 不是我们的：带摩擦从高处砸下的箱子，Box3D 会给 1–2 m/s 的横向滑移（60 m/s 砸半砖；箱子砸箱子一样）；无摩擦叠放的箱子会自己慢慢滑开（地面换成 Box3D 的箱子一样）。

桥 / fork：
- 球的暂定接触在被鬼规则丢掉之前已经登记了顶点（§12.2 的旧项，`b9e9f98` 之后更常见）。
- 内存不够的路径上，有异常挂着还接着调 JNI。
- `B3` 的静态方法绕过世界检查：过期的 world id 槽位被复用时，可能踩到别的线程的世界。
- `timer.c` 的 `s_invFrequency` 分两步写（第一次计时时两个世界竞争）。
- 512 上限时体素和 mesh 两条警告都打（同一件事打两遍）。
